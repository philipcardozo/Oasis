The browser capture found one safe first-paint optimization: `/js/util.js` was
served by the fallback static mount rather than the explicit cached asset route.
Before the patch it had no explicit `Cache-Control`, no `ETag`, and no gzip in
the captured response. After the patch, all HAR flows show:

```text
Cache-Control: public, max-age=60, must-revalidate
Content-Encoding: gzip
ETag: W/"oasis-c893a2e8e8286b3f"
Content-Length: 515
```

The route now matches `/js/main.js`, `/js/config.js`, and `/js/state.js`.

The DCF workbook route had a different transport issue: `.xlsx` files are
already ZIP-compressed, but Proxyman/HAR showed the route being passed through
gzip anyway:

```text
Before: Content-Encoding: gzip; content.size 2,695,929; HAR compression 2,997
After:  Content-Encoding: identity; Content-Length: 2,695,929; HAR compression 0
```

This is intentionally not claimed as a transfer-size win; gzip saved only about
3 KB. The improvement is avoiding compression CPU/work on an already-compressed
binary while preserving the exact workbook bytes, `ETag`, cache-control, and
download behavior.

The logo PNG route had the same class of avoidable work at a much smaller
scale: it is already compressed image data, but the response was eligible for
gzip. The route now returns identity-encoded bytes while keeping long-lived
immutable caching and `ETag` revalidation:

```text
Before: Content-Encoding: gzip; decoded 1,612 bytes; transfer 1,605 bytes
After:  Content-Encoding: identity; Content-Length: 1,612; HAR compression 0
```

This is not a transfer-size win; gzip saved 7 bytes. The value is removing
pointless per-request compression work and making compressed binary assets
explicit.

The search-intent flow had a larger waterfall issue: background MapLibre warmup
could begin while `/api/universe/bulk` was loading, even though search does not
need the map runtime. The warmup now defers until a short quiet window after the
bulk payload. Proxyman-routed HAR evidence changed:

| Search capture | Before | After |
|---|---:|---:|
| Requests | 12 | 10 |
| Transfer | 1,563.3 KB | 1,311.0 KB |
| MapLibre runtime transfer | ~258.0 KB | 0 KB |
| `/api/universe/bulk` timing | after search intent | after search intent |

MapLibre still loads when the globe/Map Studio flow needs it.

## Initial Read

The local Python-side latency is already low for most JSON routes. The biggest
remaining risks are probably browser/wire concerns rather than app handler CPU:

- first-paint waterfall and transfer size now have Proxyman-routed HAR evidence
- decoded payloads for full-world entities and universe bulk are large
- DCF workbook downloads are large even when handler latency is acceptable; the
  route now avoids redundant gzip for the already-compressed `.xlsx`
- local auth/session and map-slot p95 targets are already comfortably met
- cache, compression, and 304 behavior now have HAR fallback evidence for local
  browser flows
- expanded Proxyman-routed coverage shows entity drawer, data-quality, and
  report-preview requests are small locally and do not introduce `unpkg.com` or
  pre-paint bulk loads
- duplicate requests can be inspected in `11-browser-har-summary.json`; reload
  duplicates come from the intentional boot+reload flow, not a proven app bug

## Residual Findings

- Proxyman-routed Map interaction capture in headless Chromium logged MapLibre
  `shaderPreludeCode` errors. `18-headless-maplibre-diagnostic.json` reproduced
  the warning across three headless GL variants while `styleLoaded` and basemap
  preservation stayed true and no unclassified errors remained.
- Terrain/tile requests dominate Map Studio interaction traffic. They are
  external provider requests and need Proxyman/live-browser evidence before any
  architectural change.
- `/api/universe/bulk` is still large, but the browser HAR confirms it is not
  requested during first paint and no longer competes with MapLibre warmup
  during search.
- Auth/session and map-slot handlers should not be optimized locally unless a
  staging database or deployed reverse-proxy capture contradicts the direct HTTP,
  Proxyman-routed HTTP, and TestClient p95s. The latest 20-sample local HTTP
  rerun met targets with and without the proxy.
- Entity drawer hydration is now covered by Proxyman-routed HAR. Its only large
  transfer is the expected search-intent `/api/universe/bulk` payload; the
  drawer-specific APIs are small locally.
- The route-family probe added clean 200-status p50/p95 evidence for 37
  lower-traffic routes across assets, listings, reports, data quality, terrain
  status, map features, evidence lookup, static graph data, and sandboxed
  file-backed mutation routes. Counting only clean route probes and extra
  temp-DB HTTP operations, the audit shows `map_api` and `server_app` route
  coverage at 100%. DEM tilejson coverage uses a temporary tilejson fixture;
  the real local DEM tilejson artifact remains ungenerated.
